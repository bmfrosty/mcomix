# MComix — Continuous Scroll Feature

This is an active development session adding a **continuous scroll mode** to MComix (GTK3 Python comic viewer). All work is on the `master` branch; no separate feature branch.

---

## What was added

### New preference
`prefs['continuous scroll']` (bool, default False) in `mcomix/preferences.py`.

### UI surface
- New toggle action `continuous_scroll` wired to `window.change_continuous_scroll` in `mcomix/ui.py`
- Toolbar button (uses `mcomix-continuous-scroll` icon), View menu entry, right-click popup menu entry
- Keybinding slot `continuous_scroll` registered in `mcomix/keybindings.py` and `mcomix/event.py`
- Icon file: `mcomix/images/continuous-scroll.png` (24×24 PNG, generated by `./generate-icon`)

### Core rendering — `mcomix/main.py`
- Constants `_CONTINUOUS_BEFORE = 1`, `_CONTINUOUS_AFTER = 3` control the strip window.
- New instance attributes on `MainWindow.__init__`:
  - `_continuous_strip_pages` — list of page numbers currently rendered in the strip
  - `_continuous_y_offsets` — y pixel offset for each strip page
  - `_continuous_scaled_heights` — pixel height of each strip page
  - `_continuous_adjusting` — re-entry guard (True while programmatically moving scroll)
  - `_continuous_vadjust_handler` — signal handler ID for the vadjust `value-changed` connection
  - `_continuous_archive_direction` — `'next'`/`'previous'`/`None`; survives across `_on_file_opened` to control scroll destination when crossing archive boundaries
- `draw_image()` short-circuits to `_draw_image_continuous(scroll_to)` when the pref is on.
- `change_continuous_scroll(toggleaction)` — connects/disconnects the vadjust signal, clears strip.
- `_draw_image_continuous(scroll_to)` — builds the strip, scales images to `vis_height // 2` width, positions them in `_main_layout`, updates statusbar. Handles `scroll_to` (SCROLL_TO_START / SCROLL_TO_END). Clears `_continuous_archive_direction` after the scroll is applied.
- `_on_continuous_scroll(adjustment)` — fires on every vadjust `value-changed`. Tracks which page is at the viewport top and updates `current_page` accordingly. Schedules strip extension when near the top or bottom of the current strip.
- `_schedule_strip_extend()` — debounces via `_waiting_for_redraw` flag, fires `_do_extend_strip` via `GLib.idle_add`.
- `_do_extend_strip()` — reference-pixel approach: snapshot which page+offset is at the viewport top *before* re-rendering, restore that position after. Prevents the scroll-jump bug (136 files, current_page advancing between schedule and execution).
- `_on_file_opened()` — clears strip data, sets `_last_scroll_destination` based on `_continuous_archive_direction`. Does NOT clear `_continuous_archive_direction` here (it must survive until `_draw_image_continuous` actually renders).
- `_on_file_closed()` — clears strip data to prevent stale scroll events during archive transitions.
- `next_book()` / `previous_book()` — set `_continuous_archive_direction` before the new archive loads.
- `_update_page_information()` — guard: `if filename is None: return` (prevents TypeError when imagehandler is cleaned up mid-transition but stale scroll events still fire).
- `is_scrollable()` — returns `True` unconditionally in continuous scroll mode.
- `displayed_double()` — returns `False` in continuous scroll mode.
- `_page_available()` — in continuous scroll mode, redraws when the available page is in the current strip.

### Scroll/event handling — `mcomix/event.py`
- `_scroll_with_flipping()` — short-circuits for continuous scroll: tries `scroll()`, and if it can't move and the strip includes the last/first page, calls `_next_page_with_protection()` / `_previous_page_with_protection()` to cross archive boundaries.
- `_smart_scrolling()` — same short-circuit for smart scroll.
- `scroll_wheel_event()` — horizontal scroll (LEFT/RIGHT) is a no-op in continuous scroll mode.
- Mouse-click page-flip (`mouse_release_event`) — suppressed in continuous scroll mode.

### Icon generation
- `./generate-icon` — executable Python script (`#!/usr/bin/python3`) that writes `mcomix/images/continuous-scroll.png`.
- W_PATTERN is an 18×18 grid (1=white pixel, 0=green pixel). Each cell is one content pixel. Script adds a 3px green border on all sides → 24×24 output.
- Run it, edit the pattern, re-run to iterate.

## Bug fix timeline — "short final image scrolls back 2 pages" (690×252 last image)

**Symptom**: With 136 images (690×1000px regular, last one 690×252px), reaching the bottom of the last image causes the view to jump back ~2 pages instead of opening the next archive.

**Root cause (final)**: GTK fires `value-changed` *synchronously inside* `set_size()`. When `_draw_image_continuous()` calls `self._main_layout.set_size(vis_width, 726)` (shrinking the layout because the final short-page strip is shorter than the viewport), GTK immediately fires `value-changed` and `_on_continuous_scroll` runs. At that instant `_continuous_strip_pages` hasn't been updated yet — it still holds the previous (taller) strip. So all guards computed from strip data see the wrong state, page tracking regresses `current_page` backward, and the upward-extend cascade starts.

### Attempt 1 — FAILED
Added two guards to `_on_continuous_scroll`:
1. `at_archive_end` check to skip page-tracking regression when `last_in_strip == n_total and total_strip_h < vis_height`.
2. `total_strip_h >= vis_height` condition on the upper-extend branch.

**Why it failed**: Both guards use `_continuous_strip_pages` data, but the signal fires *before* that data is updated. The old strip (e.g. [134,135,136] with total_h=1306) makes `at_archive_end=False` and `total_strip_h>=vis_height` True, so neither guard fires.

### Attempt 2 — CONFIRMED FIX
Hold `_continuous_adjusting = True` around the `_draw_image_continuous()` call inside `draw_image()` (line ~398):
```python
self._continuous_adjusting = True
result = self._draw_image_continuous(scroll_to)
self._continuous_adjusting = False
```
`_on_continuous_scroll` already returns immediately when `_continuous_adjusting` is True. The fix ensures that the synchronous `value-changed` fired by `set_size()` during any `draw_image()` call is silenced. By the time `_continuous_adjusting` becomes False again, the strip data is fully updated and the next genuine scroll event will be handled correctly.

The Attempt 1 guards were reverted after Attempt 2 was confirmed working — they were unnecessary cruft.

## Other bugs fixed during this session

| Bug | Root cause | Fix |
|-----|-----------|-----|
| `TypeError` in `_update_page_information` during archive transition | `get_page_filename()` returns `None` when imagehandler cleaned up | `if filename is None: return` guard |
| Previous archive opens at top instead of bottom | `set_page()` call after `_on_file_opened` overwrites `_last_scroll_destination` | `_continuous_archive_direction` flag survives through multiple `_draw_image_continuous` calls; cleared only after scroll is applied |
| Stale strip data causing crashes on archive close | `_continuous_strip_pages` not cleared on file close | Clear in `_on_file_closed` |
| Scroll jumps backward near end of archive (136 files, 690×1000px) | `_do_extend_strip` deferred via idle_add; by execution time current_page advanced significantly, causing delta-based vadjust to go negative | Replaced delta approach with reference-pixel: snapshot page+offset at viewport top before re-render, restore after |
